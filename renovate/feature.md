## 2. 高度なカスタマイズ性 ⚙️

### スケジュール管理

```json
{
  "schedule": [
    "* 22-23,0-4 * * 1-5",
    "* * * * 0,6"
  ]
}
```

**cron構文の説明:**
```
* 22-23,0-4 * * 1-5
│     │     │ │  │
│     │     │ │  └─ 月～金（1-5）
│     │     │ └──── 月（任意）
│     │     └────── 日（任意）
│     └──────────── 22-23時と0-4時
└────────────────── 分（任意）

* * * * 0,6
        └─ 土日（0=日曜, 6=土曜）
```

**できること:**
- 📅 曜日・時間帯の指定（cron構文）
- 🌙 夜間のみ更新
- 🎯 業務への影響を最小化

---

### グループ化

```json
{
  "packageRules": [
    {
      "matchPackagePatterns": ["^@types/"],
      "groupName": "TypeScript type definitions"
    }
  ]
}
```

**メリット:**
- 📊 関連パッケージを一つのPRにまとめる
- 🔢 PRの数を大幅削減
- 👀 レビュー負担を軽減

---

### バージョン戦略

```
パッチ更新 (1.2.3 → 1.2.4)
  └─ 自動マージ ✅

マイナー更新 (1.2.3 → 1.3.0)
  └─ 手動レビュー 👀

メジャー更新 (1.2.3 → 2.0.0)
  └─ 慎重にレビュー ⚠️
```

## 4. CI/CDとのシームレスな統合 🔗

### 通常のPRと同じフロー

```
┌──────────────┐
│ Renovate PR  │
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ 自動テスト   │  ← 既存のCI/CD
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ ✅ テスト通過 │
│ ❌ テスト失敗 │
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ 自動/手動    │
│ マージ       │
└──────────────┘
```

### 安全な自動マージ

**必須条件:**
- ✅ すべてのCIテストが成功
- ✅ コードレビューの承認（設定による）
- ✅ Required checksをすべてクリア
- ✅ ブランチ保護ルールを満たす

## 5. Dependency Dashboardによる可視化 📊

### ダッシュボードの構成

```
┌─────────────────────────────────────────┐
│ 📦 Dependency Dashboard                 │
├─────────────────────────────────────────┤
│ ⚠️ Warning                              │
│   These dependencies are deprecated:    │
│   - old-package@1.0.0                   │
├─────────────────────────────────────────┤
│ 🚫 Edited/Blocked                       │
│   □ Update dependency A to v2.0        │
│   □ Update dependency B to v3.0        │
├─────────────────────────────────────────┤
│ ✅ Open                                 │
│   □ Update dependency C to v1.5        │
│   □ Update dependency D to v4.2        │
│   □ Update dependency E to v2.1        │
└─────────────────────────────────────────┘
```

### 表示される情報

| 項目 | 説明 |
|------|------|
| ⚠️ **Deprecated** | 非推奨になった依存関係 |
| 🚫 **Edited/Blocked** | 手動編集でブロックされた更新 |
| ✅ **Open** | 作成済みの更新PR一覧 |
| ☑️ **Checkbox** | 一括操作が可能 |

### メリット

- 👀 **一目瞭然**: 古いライブラリがすぐわかる
- 📋 **Issue的な使い方**: チームで状況共有
- 🎯 **直感的**: 技術的知識が少なくても理解しやすい

## 6. プリセットと共有可能な設定 🔧

### プリセット設定

```json
{
  "extends": ["config:recommended"]
}
```

**用意されているプリセット例:**
- `config:recommended` - 推奨設定
- `schedule:weekends` - 週末のみ実行
- `:automergeMinor` - マイナー更新を自動マージ
- その他多数

---

### 組織内での設定共有

```
┌─────────────────────────┐
│ 組織共通設定            │
│ (renovate-config.json)  │
└───────────┬─────────────┘
            │
    ┌───────┼───────┐
    │       │       │
    ▼       ▼       ▼
┌─────┐ ┌─────┐ ┌─────┐
│Repo1│ │Repo2│ │Repo3│
└─────┘ └─────┘ └─────┘
```

**メリット:**
- 🏢 組織全体で統一された管理
- 🔄 一度の設定変更で全リポジトリに適用
- 📏 一貫性のある運用ルール
